## 你关心的点（先答）
- `pnpm install` 本身很难做到“完全无软链”的 `node_modules`（pnpm 的核心机制就是用软链/硬链指向 store）。
- 所以我不会要求 pnpm 产出“nolink node_modules”，而是在**打包阶段**把现有 `node_modules` **解引用复制**成一个“无软链”的真实文件树，再封装进离线包。
- 你建议的“先删掉 pnpm 安装的包再重新 install”是对的：这样可以避免旧残留导致 bundle 不可复现。

## 目标
- 产出一个离线包（tar.gz/zip）+ 启动器脚本，用户拿到后执行启动器即可安装。
- 安装后获得 `openclaw` 命令，使用体验等同 `npm install -g`（直接 `openclaw ...`）。
- 离线包内 `node_modules` **不包含任何软链**。

## 方案A（按你要求优先采用）
### 1) 清理并重新安装依赖（可复现基线）
- 删除当前 pnpm 安装产物：
  - 根目录 `node_modules/`
  - （可选）pnpm store 做一次清理（避免旧包影响体积/一致性）
- 重新安装：`pnpm install`（按 lockfile）
- 构建：`pnpm build`

### 2) 生成“无软链 runtime tree”并打包
新增一个打包脚本（例如 `scripts/bundle-offline.sh`），流程：
- 生成 staging 目录：`dist/offline/openclaw-<version>-<platform>-<arch>/`
- 拷贝运行时所需文件（先全量，后续可裁剪）：
  - `dist/`、`openclaw.mjs`、`package.json`
  - `extensions/`、`skills/`、`assets/`、`docs/`
  - （若你保留 bailey stub）`stubs/`
- **关键：无软链复制 node_modules**
  - 用“解引用复制”把根目录的 `node_modules/` 复制到 staging：
    - macOS/Linux：优先 `rsync -aL node_modules/ <staging>/node_modules/`（`-L` 跟随软链）
    - 备选：`cp -R -L -p node_modules <staging>/node_modules`
  - 复制完成后，staging 里的 `node_modules` 就是普通文件/目录结构（无软链）。
- 打包产物：输出 `openclaw-offline-<version>-<platform>-<arch>.tar.gz`

### 3) 启动器安装脚本（离线安装）
新增 `scripts/install-offline.sh`（随离线包一起发给用户），支持：
- `--prefix`：默认安装到 `~/.openclaw-offline`（或你指定的目录）
- `--bin-dir`：默认优先 `/usr/local/bin`（可写则用），否则用 `~/.local/bin`
- 安装步骤：
  - 解压离线包到 `<prefix>/lib/openclaw`（或 `<prefix>/openclaw`）
  - 检测系统 `node` 版本满足 `>=22.12.0`
  - 写入 wrapper：`<bin-dir>/openclaw` -> `exec node <installDir>/openclaw.mjs "$@"`
  - 输出 PATH 提示（如果 `bin-dir` 不在 PATH）

## 重要说明（平台/架构）
- 由于原生依赖，离线包必须在目标平台构建并打包：
  - 你在 macOS arm64 打出来的包，只能给 macOS arm64 用。
- 我会让打包脚本把平台/架构写进产物名，防止装错。

## 验证
- 在本机用临时前缀安装验证：
  - 运行 `<bin-dir>/openclaw --version`
  - 再跑一个轻量命令（例如 `openclaw help`）确认 CLI 能正常启动。

## 后续可选优化（不影响第一版交付）
- 做“单文件自解压启动器”（脚本尾部附带 tar.gz payload），用户只需要下载 1 个文件执行。
- 做 runtime 裁剪（只带实际用到的 extensions/docs），缩小体积。
